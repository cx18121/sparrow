# Product

## Register

product

## Users

Sparrow is for students doing cold outreach. They are usually balancing classes, clubs, internships, recruiting, founder outreach, sponsorship asks, or networking work, so they need a tool that helps them move quickly without making outreach feel careless or generic.

Their primary job is to find relevant people, keep leads organized, generate useful first drafts, edit those drafts, and send or track outreach without getting lost in process overhead.

## Product Purpose

Sparrow helps students turn lead lists and personal context into practical outbound email workflows. It combines discovery, contacts, campaigns, templates, drafts, and Gmail sending into one authenticated workspace.

Success means a student can go from a target company or contact list to reviewed, personalized outreach with less manual copying, fewer lost drafts, and clearer status for what has been sent.

## Brand Personality

Fast, useful, practical.

The interface should feel clean, direct, and lightweight. It should support repeated work: scanning tables, reviewing drafts, editing copy, and moving between outreach stages. It should not try to entertain the user or over-explain itself.

## Anti-references

Avoid anything that looks like generic AI slop: decorative gradients, vague productivity copy, oversized marketing composition inside the app, repetitive icon cards, glassy surfaces, fake complexity, or visual effects that do not help the workflow.

Avoid dark mode as the default unless a specific future workflow calls for it. The current product should stay in a clean light-mode direction.

## Design Principles

1. Make the next action obvious. Students should always know whether they are discovering, drafting, reviewing, sending, or configuring.
2. Prioritize speed over ceremony. The UI should reduce clicks, avoid unnecessary confirmations, and keep common outreach tasks close at hand.
3. Make generated work inspectable. AI output should appear as editable drafts with clear recipient context, not as magic output hidden behind vague states.
4. Keep status visible. Sent, draft, loading, failed, and connected states should be explicit so the user does not have to infer what happened.
5. Stay clean without becoming generic. Use restraint, strong hierarchy, and precise spacing instead of stock SaaS decoration.

## Accessibility & Inclusion

No special accessibility target has been set yet. Default to sound product practice: semantic controls, visible focus states, readable contrast, keyboard-accessible workflows, and respect for reduced-motion preferences where animation is used.
