Output: A validated Prisma schema (Company, Contact, UserLead, LeadStatus), a Prisma singleton, region normalization utility, role normalization utility, upsert helper functions, a manual-add CLI script, vitest config, and test stubs.

Note: LEAD-01 (filterable dashboard UI) and LEAD-04 (bulk-select + batch email trigger) are NOT addressed in this plan. The schema lays the data foundation for those features, but the UI is Phase 3 scope.

**Model Company** (shared pool, no userId):
- `id` String @id @default(cuid())
- `name` String
- `domain` String @unique — THIS IS THE UPSERT KEY
- `description` String? @db.Text
- `oneLiner` String?
- `website` String?
- `stage` String? — values: "Pre-Seed", "Seed", "Series A", "Series B", "Series C+", "Public"
- `industry` String? — e.g. "B2B Software", "Healthcare", "Fintech"
- `subIndustry` String?
- `location` String? — raw string from source
- `region` String? — normalized at ingestion: "Bay Area", "New York", "Remote", etc.
- `headcount` Int? — team_size from YC
- `isHiring` Boolean @default(false)
- `batch` String? — YC-specific: "W24", "S23"
- `source` String — "yc" | "producthunt" | "wellfound" | "manual"
- `sourceId` String? — source-native ID for dedup
- `lastScrapedAt` DateTime?
- `createdAt` DateTime @default(now())
- `updatedAt` DateTime @updatedAt
- Relations: contacts Contact[], userLeads UserLead[]
- Indexes: @@index([stage]), @@index([industry]), @@index([region]), @@index([isHiring]), @@index([source]), @@index([headcount])

**Model Contact** (shared pool, no userId):
- `id` String @id @default(cuid())
- `companyId` String
- `company` Company @relation(fields: [companyId], references: [id])
- `name` String?
- `email` String? @unique — THIS IS THE UPSERT KEY
- `title` String? — raw title: "CTO", "Founder", etc.
- `role` String? — normalized: "technical", "founder", "business", "other"
- `linkedinUrl` String?
- `source` String — "apollo" | "yc" | "manual"
- `lastVerifiedAt` DateTime? — set on each successful enrichment, SEPARATE from updatedAt
- `createdAt` DateTime @default(now())
- `updatedAt` DateTime @updatedAt
- Relations: userLeads UserLead[], emails Email[]
- Indexes: @@index([companyId]), @@index([role]), @@index([lastVerifiedAt])

**Model UserLead** (per-user, scoped by userId):
- `id` String @id @default(cuid())
- `userId` String
- `companyId` String
- `company` Company @relation(fields: [companyId], references: [id])
- `contactId` String?
- `contact` Contact? @relation(fields: [contactId], references: [id])
- `status` LeadStatus @default(NEW)
- `notes` String? @db.Text
- `addedAt` DateTime @default(now())
- `updatedAt` DateTime @updatedAt
- Relations: emails Email[]
- Constraints: @@unique([userId, companyId, contactId])
- Indexes: @@index([userId]), @@index([status])

**Enum LeadStatus**: NEW, SAVED, EMAILED, REJECTED

**Model Email** (stub for Phase 3 — prevents migration churn):
- `id` String @id @default(cuid())
- `userLeadId` String
- `userLead` UserLead @relation(fields: [userLeadId], references: [id])
- `contactId` String
- `contact` Contact @relation(fields: [contactId], references: [id])
- `subject` String?
- `body` String? @db.Text
- `status` String @default("draft")
- `sentAt` DateTime?
- `createdAt` DateTime @default(now())
- `updatedAt` DateTime @updatedAt
- Indexes: @@index([userLeadId]), @@index([contactId])

NOTE: Do NOT add a User model — that lives in Supabase Auth. The `userId` fields on UserLead reference Supabase auth user IDs as plain strings (no FK to a local User table in this phase).

**2. `scripts/_lib/region-map.ts`** — Static city-to-region lookup:
- Export `REGION_MAP: Record<string, string>` with these exact entries:
  - "san francisco" -> "Bay Area", "sf" -> "Bay Area", "san jose" -> "Bay Area", "palo alto" -> "Bay Area", "mountain view" -> "Bay Area", "menlo park" -> "Bay Area", "sunnyvale" -> "Bay Area", "oakland" -> "Bay Area", "berkeley" -> "Bay Area", "redwood city" -> "Bay Area"
  - "new york" -> "New York Metro", "nyc" -> "New York Metro", "brooklyn" -> "New York Metro", "manhattan" -> "New York Metro"
  - "seattle" -> "Pacific Northwest", "bellevue" -> "Pacific Northwest", "portland" -> "Pacific Northwest"
  - "boston" -> "Boston / Cambridge", "cambridge" -> "Boston / Cambridge"
  - "austin" -> "Austin", "los angeles" -> "Los Angeles", "la" -> "Los Angeles", "santa monica" -> "Los Angeles"
  - "chicago" -> "Chicago", "denver" -> "Denver / Boulder", "boulder" -> "Denver / Boulder"
  - "london" -> "London", "berlin" -> "Berlin", "toronto" -> "Toronto", "bangalore" -> "Bangalore", "singapore" -> "Singapore"
  - "remote" -> "Remote"
- Export `normalizeRegion(rawLocation: string | null): string | null`:
  - If null/empty, return null
  - Lowercase the input, iterate REGION_MAP entries, return region if key is found via `includes()`
  - If no match, return the raw string unchanged

**3. `scripts/_lib/role-normalizer.ts`** — Title-to-role mapping:
- Export `normalizeRole(title: string | null): string | null`:
  - If null/empty, return null
  - Lowercase the title
  - If includes "founder" or "co-founder" or "ceo" -> return "founder"
  - If includes "cto" or "engineer" or "developer" or "technical" or "vp eng" or "head of eng" -> return "technical"
  - If includes "sales" or "marketing" or "growth" or "biz dev" or "business" or "cmo" or "cro" -> return "business"
  - Otherwise return "other"

**4. `scripts/_lib/upsert.ts`** — Idempotent upsert helpers:
- Import `prisma` from `./prisma.ts`
- Import `normalizeRegion` from `./region-map.ts`
- Import `normalizeRole` from `./role-normalizer.ts`

- Define and export TypeScript interface `CompanyInput`:
  ```
  { domain: string; name: string; description?: string | null; oneLiner?: string | null;
    website?: string | null; stage?: string | null; industry?: string | null;
    subIndustry?: string | null; location?: string | null; headcount?: number | null;
    isHiring?: boolean; batch?: string | null; source: string; sourceId?: string | null; }
  ```

- Define and export TypeScript interface `ContactInput`:
  ```
  { companyId: string; email: string; name?: string | null; title?: string | null;
    linkedinUrl?: string | null; source: string; }
  ```

- Export `async function upsertCompany(data: CompanyInput): Promise<Company>`:
  - Uses `prisma.company.upsert()` with `where: { domain: data.domain }`
  - `update` sets: name, description, oneLiner, website, stage, industry, subIndustry, location, region (via `normalizeRegion(data.location)`), headcount, isHiring (default false), batch, lastScrapedAt (new Date())
  - `create` sets: all update fields PLUS domain, source, sourceId
  - Returns the upserted company record

- Export `async function upsertContact(data: ContactInput): Promise<Contact | null>`:
  - If `!data.email`, return null (contacts without email are useless for outreach)
  - Uses `prisma.contact.upsert()` with `where: { email: data.email }`
  - `update` sets: name, title, role (via `normalizeRole(data.title)`), linkedinUrl, lastVerifiedAt (new Date())
  - `create` sets: all update fields PLUS companyId, email, source
  - Returns the upserted contact record

**5. `scripts/manual-add.ts`** — CLI entrypoint for DISC-05 (manual add company/contact):
- Import `dotenv/config`
- Import `prisma` from `./_lib/prisma.ts`
- Import `upsertCompany`, `upsertContact` from `./_lib/upsert.ts`

- Parse CLI args using `process.argv.slice(2)`:
  - `--domain <domain>` (required)
  - `--name <name>` (optional, defaults to domain)
  - `--email <email>` (optional, creates contact if provided)
  - `--title <title>` (optional, contact title)
  - `--industry <industry>` (optional)
  - `--stage <stage>` (optional)
  - `--location <location>` (optional)

- Simple arg parser: iterate argv, match `--key` and take next arg as value

- If `--domain` is missing, print usage and exit 1:
  ```
  Usage: npx tsx scripts/manual-add.ts --domain example.com [--name "Acme Inc"] [--email ceo@example.com] [--title "CEO"] [--industry "B2B Software"] [--stage "Seed"] [--location "San Francisco"]
  ```

- Call `upsertCompany({ domain, name, industry, stage, location, source: "manual" })`
- Log: `"Added/updated company: ${company.name} (${company.domain})"`

- If `--email` provided:
  - Call `upsertContact({ companyId: company.id, email, name: name || null, title: title || null, source: "manual" })`
  - Log: `"Added/updated contact: ${email} at ${company.domain}"`

- Disconnect prisma at end
- Export the main function as `manualAdd` for testability
